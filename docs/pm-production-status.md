## 关键风险 / 掉线点

### 风险 1：版本口径不一致
- 当前已验证状态依赖工作区未提交改动。
- 如果 main 现在只看 Git `HEAD`，会误以为 `79f7167` 就是最新可交付版；实际上不是。
- 这会直接影响：
  - QA 取版
  - 试玩链接取版
  - 交付回溯
  - 问题复现

### 风险 2：并行线成果没有统一“落版动作”
- UI 线、玩法精修线、构建线都在前进，但没有一个明确的“本轮版本冻结 / 收口 / 提交 / 打标”动作。
- 结果就是：文档越来越完整，但源码和构建仍可能漂在工作区。

### 风险 3：任务定义开始模糊
- 当前最容易掉进的坑是“继续 polish 一点点”。
- 但如果没有明确任务边界，就会出现：
  - UI 继续改一点
  - 演出继续补一点
  - 玩法再调一点
  - 最后谁都做了，但没人收版本

### 风险 4：构建产物是验证副作用
- 现有 `release_guard.sh` 会重导出并同步构建目录，这是好事；
- 但它也意味着**只要做验证，就会改工作区**。
- 如果没有“验证后如何收版”的规定，工作区会长期处在脏状态。
