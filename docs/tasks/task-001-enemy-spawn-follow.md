# Task 001 - 敌人生成与追踪系统

## 任务类型
功能研发任务 / V0 核心玩法实现 / 多 Agent 协作首轮任务单

## 目标
在 `survivor-demo` 中实现最小可玩的“敌人生成与追踪系统”，让场景能够持续生成敌人，并使敌人稳定朝玩家移动，为后续自动攻击、受击、经验掉落与升级系统提供基础。

## 背景
当前项目已完成初始化与玩家移动基础：

- `game/scenes/main.tscn` 已加载主场景与玩家实例
- `game/scripts/main.gd` 仅有启动打印，没有战斗循环逻辑
- `game/scenes/player.tscn` 与 `game/scripts/player.gd` 已支持 8 向移动
- `docs/roadmap.md` 中“敌人生成与追踪”是初始化和玩家移动之后的下一个核心里程碑

因此，本任务是 V0 的第一项战斗系统任务，目标不是一次性做完整战斗，而是先建立可扩展的敌人生成与追踪闭环。

## 输入
### 项目文档
- `docs/GDD.md`：项目类型为 2D 割草 Roguelike
- `docs/tech_design.md`：技术栈为 Godot 4.x + GDScript，结构为 scene + script + data
- `docs/roadmap.md`：当前排期中“敌人生成与追踪”位于玩家移动之后
- `docs/status.md`：当前处于初始化完成、等待正式任务拆分阶段

### 当前工程结构
- `game/scenes/main.tscn`
- `game/scenes/player.tscn`
- `game/scripts/main.gd`
- `game/scripts/player.gd`
- `game/assets/placeholder/`
- `game/data/`

## 输出
建议本任务至少产出以下内容：

1. **敌人场景**
   - 新建敌人 scene，例如 `game/scenes/enemy_basic.tscn`
   - 具备基础可视节点与碰撞节点

2. **敌人脚本**
   - 新建敌人行为脚本，例如 `game/scripts/enemy_basic.gd`
   - 逻辑包含：获取玩家目标、朝玩家移动、基础移动参数

3. **生成器逻辑**
   - 在主场景或独立生成器节点中实现定时生成
   - 支持基础刷新频率控制
   - 敌人生成位置应尽量在玩家视野外或场景边缘附近，避免直接贴脸生成

4. **主场景接线**
   - `main.tscn` / `main.gd` 完成玩家引用、敌人实例化、敌人容器管理

5. **可调参数**
   - 至少暴露以下参数供 Designer / Programmer 后续迭代：
     - 敌人移动速度
     - 生成间隔
     - 单次生成数量
     - 生成半径或生成边界

6. **必要说明**
   - 若实现中新增数据配置文件、节点层级约定或依赖关系，需同步写入相关文档或代码注释

## 验收标准
满足以下条件即可视为本任务通过：

1. 运行主场景后，能够自动周期性生成敌人
2. 敌人生成后能够持续朝玩家移动，而非静止或随机游走
3. 玩家移动时，敌人会更新追踪方向，表现出持续追逐
4. 场景中可同时存在多个敌人，且不会因基础逻辑错误立即报错
5. 核心参数可在编辑器或脚本导出变量中调整
6. 代码与场景命名清晰，放置位置符合当前项目结构
7. 不要求本阶段实现攻击、伤害、死亡、掉落、动画状态机等完整战斗内容

## 限制
1. **范围限制**：本任务仅覆盖“生成 + 追踪”闭环，不扩展到完整战斗系统
2. **技术限制**：使用 Godot 4.x 与 GDScript；沿用现有 scene + script + data 结构
3. **资源限制**：优先使用占位资源或基础图形，不阻塞程序验证
4. **复杂度限制**：V0 阶段不强求复杂寻路、群体避让、性能优化或敌人种类系统
5. **协作限制**：
   - Designer 先定义敌人基础表现与生成规则边界
   - Programmer 先做最小可运行版本，避免过早抽象
6. **可扩展性要求**：实现方式应为后续自动攻击、碰撞受击、经验掉落保留清晰扩展点

## 协作建议
### 建议先交给 Designer
- 定义 V0 基础敌人的体型、颜色、朝向表现与占位资源方案
- 定义生成规则基线：刷新节奏、同时存在数量预期、出生区域原则
- 明确玩家与敌人的空间关系体验目标：压迫感、追逐速度差、初始难度

### 建议随后交给 Programmer
- 按当前任务单完成敌人 scene / script / spawner / main 接线
- 先实现一个基础敌人原型，不要一开始就做多敌种架构
- 用导出参数保证后续 Designer 能低成本调数值
