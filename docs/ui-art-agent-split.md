# UI / 美术 Agent 拆分建议

## 背景
当前 demo 的玩法闭环已经够用，下一阶段最值钱的提升，不是继续加更多系统，而是把“能玩”提升到“看起来像一个方向明确的产品样片”。

已知方向：**西游记古风 Q 版**。

因此 UI / 美术不建议继续混在一个笼统任务里推进，而应至少拆成可并行的两条线；如果资源允许，建议拆成三到四个 agent。

---

## 推荐拆分方式

## 方案一：最小可用拆分（推荐当前项目先这样做）

### Agent A：UI / HUD 收口 Agent
职责：
- 整理当前 HUD 信息层级
- 统一按钮、面板、弹窗、横幅、提示文案风格
- 输出低保真线框、信息优先级、响应式摆位规则
- 明确桌面 / 移动端共同布局与差异布局

输入：
- 当前可玩 Web demo
- 现有 HUD 字段与交互按钮
- `docs/release-acceptance.md`

输出：
- UI 信息架构说明
- HUD 改版清单
- 按钮 / 面板 / 提示文案规范
- 移动端触控区域建议

验收标准：
- 玩家第一次进入就知道怎么移动、怎么闪避、目标是什么
- HUD 不再像开发态信息堆叠，而是有主次和阅读顺序
- 桌面和移动端都能看清核心状态

### Agent B：视觉设定 / 美术方向 Agent
职责：
- 把“西游记古风 Q 版”拆成可执行视觉规范
- 定义主角、敌人、经验球、投射物、按钮、面板的风格关键词
- 输出颜色、线条、材质感、图标语言、命名语气
- 给后续像素 / 2D 素材制作提供统一标准

输入：
- 当前 demo 截图
- `docs/worklog.md` 中已确认的视觉方向
- `docs/GDD.md`

输出：
- 风格关键词
- 色板建议
- UI 装饰元素建议
- 玩家 / 敌人 / 可拾取物 / 投射物视觉命名规范
- 替换优先级列表

验收标准：
- 团队成员看到文档后，能知道“什么叫西游记古风 Q 版”，而不是各自理解
- UI 和角色美术不会做成两个完全不同的世界观

---

## 方案二：标准并行拆分（资源更充足时推荐）

### Agent 1：UI/UX 策划 Agent
重点：
- 信息架构
- 页面 / HUD 线框
- 交互路径
- 新手引导与提示文案

### Agent 2：UI 视觉落地 Agent
重点：
- 按钮、面板、横幅、图标、血条、经验条
- Godot 内 Theme / HUD 资源组织
- 分辨率适配与移动端可读性

### Agent 3：角色 / 敌人美术设定 Agent
重点：
- 主角视觉原型
- 基础敌人 / 快速敌人 / 重装敌人 / 精英敌人风格统一
- 西游记要素映射（如小妖、山精、巡山喽啰等语义方向）

### Agent 4：特效 / 轻演出 Agent
重点：
- 受击闪白升级为更统一的视觉语言
- 升级、闪避、精英波次、Demo Clear 的演出层
- 命中特效、掉落吸附、提示横幅轻动效

---

## 为什么不建议只放一个“UI美术综合 Agent”
因为它很容易出现下面的问题：
- 一边改 HUD 排版，一边改角色风格，任务边界混乱
- 交互问题和视觉问题混在一起，验收标准模糊
- 最后大家都在“提感觉”，但没有清晰产出物

对当前项目来说，**至少把“信息层级”与“视觉方向”拆开**，效率会明显高很多。

---

## 当前项目建议的优先顺序

### 第 1 优先级：UI / HUD 收口 Agent
先解决：
- 现在屏幕上哪些信息必须看
- 哪些信息是开发态临时信息
- 桌面和移动端操作提示如何更自然
- `03:00` 通关目标如何被更明确地感知

### 第 2 优先级：视觉设定 / 美术方向 Agent
再解决：
- 西游记古风 Q 版的统一视觉语言
- 主角与敌人的命名 / 轮廓 / 配色关系
- 经验球、投射物、按钮、面板不要彼此割裂

### 第 3 优先级：UI 视觉落地 Agent
在规范已明确后，再把：
- HUD 资源
- 按钮样式
- 图标
- 横幅和弹窗

真正替换进 Godot 工程。

---

## 建议的协作接口
为了避免 agent 之间反复打架，建议固定接口：

### UI / HUD 收口 Agent 输出给其他人
- HUD 字段清单
- 布局线框
- 优先级定义
- 关键文案草案

### 视觉设定 Agent 输出给其他人
- 色板
- 风格关键词
- 参考方向
- 角色 / 敌人 / UI 装饰元素规则

### UI 视觉落地 Agent 接收并实施
- 把线框 + 视觉规范落实为 Godot 内实际资源
- 输出 prefab / scene / theme / sprite 资源替换清单

---

## 对当前 demo 的具体拆任务建议

### UI / HUD 收口 Agent 可以直接接的任务
- 重排 HUD：生命、经验、时间、波次、击杀、武器信息主次重组
- 统一提示文案：开始提示、聚焦提示、Demo Clear、Game Over、重开提示
- 移动端触控区视觉弱化但仍可识别
- 补一个“当前目标：生存至 03:00”的常驻或阶段提示方案

### 视觉设定 / 美术方向 Agent 可以直接接的任务
- 定义主角基础轮廓：小悟空 / 小行者系还是更泛化西游少年英雄
- 定义三种敌人 + 精英敌人的语义映射与轮廓差异
- 设定按钮、面板、边框、卷轴、云纹、法器等古风 Q 版元素使用边界
- 定义伤害数字、经验球、投射物的视觉语言

### UI 视觉落地 Agent 后续接入任务
- 把 HUD、按钮、横幅做成 Godot 可替换资源
- 做 1280x720 基线下的桌面布局
- 做移动端安全区和按钮遮挡优化

---

## 最终建议
对 `survivor-demo` 这个体量，当前最合理的拆法是：

1. **UI / HUD 收口 Agent**
2. **视觉设定 / 美术方向 Agent**
3. （可选）**UI 视觉落地 Agent**
4. （可选）**特效 / 轻演出 Agent**

也就是说：
- 先拆成 2 条主线就够用
- 不要一上来拆成 6、7 个小 agent
- 等视觉规范稳定后，再加落地类 agent

这样最符合当前项目阶段：先把交付面和视觉方向定住，再继续扩内容。
