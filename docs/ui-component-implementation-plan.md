# survivor-demo HUD / 结算页 Godot 可复用 UI 组件落地清单

> 目标：承接已完成的 UI 方向板、提示词包、低保真线框，把 HUD 与结算页进一步整理成 **Godot 可实装但暂不改玩法逻辑** 的组件规划文档。
>
> 风格主轴：**戏台战报风**；辅助语汇：**云纹卷轴风**。

---

## 0. 本文定位
- 类型：设计落地准备 / UI 组件规划
- 覆盖范围：
  - **HUD（局内常驻 UI）**
  - **结算页（胜 / 败 / 暂停共骨架）**
- 本轮不做：
  - 不改游戏运行逻辑
  - 不新增玩法数据字段
  - 不直接替换现有 Godot 场景中的 UI 节点
  - 不要求本轮完成 AI 出图或正式切图

---

## 1. 落地原则

### 1.1 先组件化，再美术化
先把能稳定复用的 UI 骨架抽出来，再决定哪些边角要补 AI 资产。不要先画整张大图再硬切。

### 1.2 Web 体量优先轻量
当前网页版本已经存在 wasm 加载压力，因此 UI 资源策略应尽量遵守：
- **底板、描边、分隔线、纯色按钮优先程序绘制**
- **小装饰、牌匾头尾、印章、角花优先少量贴片资产**
- 避免大面积整图背景依赖 HUD

### 1.3 同一语义，同一组件
桌面横屏与手机竖屏尽量共用一套组件，只改：
- 容器排布
- 字体缩放
- 可选字段显隐
- 安全区与边距

### 1.4 状态变化优先靠主题切换，不靠重做一套图
比如告急、升级播报、胜利、失败，应优先通过：
- 颜色 token
- 文案 token
- 局部徽签 / 印章 / 高亮贴片
实现，而不是每个状态都重画一整页。

## 2. 推荐的 Godot UI 组织方式

## 2.1 组件层级建议
建议先抽成两层：

### A. 基础皮肤层（通用原子件）
复用给 HUD 与结算页：
- `ui_panel_base`
- `ui_section_divider`
- `ui_badge_tag`
- `ui_title_plaque`
- `ui_action_button`
- `ui_stamp_badge`
- `ui_stat_row`

### B. 页面组合层（业务组合件）
由基础皮肤层拼装：
- `hud_main_panel`
- `hud_broadcast_banner`
- `hud_status_tag`
- `hud_action_tray`
- `settlement_report_panel`
- `settlement_comment_stamp_row`
- `settlement_cta_tray`

## 2.2 推荐节点思路（不强制）
本轮不要求改场景，但后续 Godot 落地可优先考虑：
- 容器：`MarginContainer` / `HBoxContainer` / `VBoxContainer` / `GridContainer`
- 面板：`PanelContainer` 或自绘 `Control`
- 文本：`Label` / `RichTextLabel`
- 图标 / 印章：`TextureRect`
- 状态切换：主题覆盖、shader 参数、贴图替换、显隐控制

## 3. 基础皮肤层组件清单

## 3.1 `ui_panel_base`
### 用途
统一 HUD 面板、卷轴底板、操作带底板的基础承载。

### 结构建议
- 底色层
- 描边层
- 内边距
- 可选分隔槽位
- 可选角花槽位

### 程序绘制 / 资产建议
- **优先程序绘制**：底色、圆角、描边、内阴影、分隔线
- **可选 AI 资产**：四角云纹 / 铜钉 / 描金花角小贴片

### 状态变体
- 常态：墨褐底 + 暖金描边
- 弱化：更低对比，用于操作带
- 告急：边框偏朱砂
- 高亮：边框与标题槽偏暖金

---

## 3.2 `ui_section_divider`
### 用途
在主账本、战报面板内拆分数据区，避免信息糊成一块。

### 程序绘制 / 资产建议
- **程序绘制**：1~2 px 金线 / 暖褐线 / 半透明压纹线
- **不建议单独出图**

### 状态变体
- 常态
- 弱化
- 高亮分段（用于结果页重点统计）

---

## 3.3 `ui_badge_tag`
### 用途
承载 HUD 的军令签 / 告急签 / 压阵签，以及播报类别签。

### 结构建议
- 标签底片
- 短文本
- 可选小图标 / 章纹位

### 程序绘制 / 资产建议
- **底片可程序绘制**：矩形、圆角、描边、渐变
- **建议 AI 资产辅助**：签头切角、戏台纹头、轻微纸签边缘

### 状态变体
- 军令
- 告急
- 压阵
- 修为
- 喝彩
- 中性类别签（妖潮播报 / 战报播报）

---

## 3.4 `ui_title_plaque`
### 用途
顶部播报条主标题区、结算页题头牌匾共用的标题视觉骨架。

### 结构建议
- 中间可拉伸标题底板
- 左右装饰头尾
- 主标题文本
- 副标题 / 副签插槽

### 程序绘制 / 资产建议
- **中段底板可程序绘制 / 9-slice**
- **头尾更适合 AI 资产**：戏台牌匾端头、卷轴卷边、金箍式装饰

### 状态变体
- HUD 播报细长版
- 结算页题头宽版
- 胜利 / 失败 / 暂停三套配色

---

## 3.5 `ui_action_button`
### 用途
统一局内暂停、结算页 CTA、次级功能按钮。

### 结构建议
- 按钮底
- 文本
- 焦点 / 按下 / 禁用反馈
- 可选副标签位

### 程序绘制 / 资产建议
- **优先程序绘制**：底色、描边、阴影、按压反馈
- **AI 资产只补局部**：按钮边角纹、主 CTA 顶部纹头

### 状态变体
- 主 CTA：朱砂高亮
- 次 CTA：深墨金边
- 辅 CTA：低权重
- Hover / Pressed / Disabled / Focused

---

## 3.6 `ui_stamp_badge`
### 用途
承载结算页印章、徽签、小结论钉子。

### 程序绘制 / 资产建议

- 程序只负责缩放、着色、透明度与布局

### 状态变体
- 胜
- 败
- 歇
- 可扩：优 / 稳 / 惊险

---

## 3.7 `ui_stat_row`
### 用途
统一显示“标签 + 数值”或“双列统计”。

### 程序绘制 / 资产建议
- **程序绘制 / 文本布局即可**
- 不建议为这一层单独出图

### 状态变体
- 单行左右分栏
- 双列网格
- 高亮数值
- 紧凑移动版

## 4. HUD 组合组件清单

## 4.1 `hud_main_panel`
### 作用
左上主账本；局内最稳定的长期信息容器。

### 推荐内容结构
- 顶部：小标题或类别签（可选）
- 中部统计：
  - 命火
  - 修为
  - 斩妖
  - 第几劫 / 波次
- 底部：当前目标一句话
- 可选：连斩（桌面默认显示，手机可降级）

### 可复用子件
- `ui_panel_base`
- `ui_section_divider`
- `ui_stat_row`
- `ui_badge_tag`

### 程序绘制 / 资产建议
- **程序绘制优先**：底板、分隔线、标签、数据排版
- **AI 资产辅助**：账本角花、铜钉、轻戏台纹头

### 需要的状态变体
- 常态
- 告急（命火低）
- 升级可选 / 终局压阵（可只变局部高亮）
- 桌面展开版 / 手机压缩版

### 实装注意点
- 文本行高与数字宽度要稳定，避免数值跳动导致布局抖动
- 当前目标区应允许 1 行优先、必要时最多 2 行

---

## 4.2 `hud_broadcast_banner`
### 作用
顶部播报条；处理短时关键事件，如阶段切换、升级、妖潮播报。

### 推荐内容结构
- 主标题
- 副签 / 类别签
- 可选短时入场动画位

### 可复用子件
- `ui_title_plaque`
- `ui_badge_tag`

### 程序绘制 / 资产建议
- **中段与文字布局可程序化**
- **牌匾头尾更适合 AI 资产**

### 需要的状态变体
- 妖潮播报
- 修为播报
- 战报播报
- 终局播报
- 升级提示

### 实装注意点
- 这是短时信息，不要占太高高度
- 动画优先做平移 / 淡入，不要做重粒子

---

## 4.3 `hud_status_tag`
### 作用
右上状态签；只表达“此刻最重要的一句话”。

### 推荐内容结构
- 徽签标签
- 正文一行

### 可复用子件
- `ui_panel_base` 或轻量底板
- `ui_badge_tag`

### 程序绘制 / 资产建议
- **主体可程序绘制**
- **签头与边缘可用小贴片增强风格**

### 需要的状态变体
- 军令
- 告急
- 压阵
- 暂歇
- 喝彩

### 实装注意点
- 文案长度要严格限制；移动端正文建议 8~12 字优先
- 状态切换频率不能过高，否则会让玩家忽视它

---

## 4.4 `hud_action_tray`
### 作用
底部操作带；承接暂停、当前法术、辅助说明。

### 推荐内容结构
- 左：暂停 / 快捷键
- 中：当前法术或当前状态
- 右：移动端可选行动提示或辅助说明

### 可复用子件
- `ui_panel_base`
- `ui_action_button`
- `ui_badge_tag`

### 程序绘制 / 资产建议
- **应以程序绘制为主**
- 装饰压到最轻，不建议为其投入重资产

### 需要的状态变体
- 桌面长条版
- 手机缩窄版
- 暂停态
- 可升级提醒态

### 实装注意点
- 移动端必须避免遮挡摇杆、闪避按钮与底部安全区
- 优先功能清晰，不追求重装饰

## 6. 组件资产分类：程序绘制 vs AI 出图 vs 混合方案

## 6.1 优先程序绘制的组件
这些组件与布局关系强、状态多、后续改动频繁，最适合先程序化：
- `ui_panel_base`
- `ui_section_divider`
- `ui_stat_row`
- `ui_action_button`
- `hud_action_tray`
- `settlement_cta_tray`
- `settlement_report_panel` 主体底板
- `hud_main_panel` 主体底板

### 原因
- 迭代快
- 资源成本低
- Web 体量可控
- 更容易适配桌面 / 手机尺寸变化

## 6.2 更适合后续 AI 出图资产的部分
这些更偏风格钉子，适合少量高识别贴片：
- 牌匾头尾装饰
- 卷轴头尾 / 卷边
- 印章 / 徽签章纹
- 角花 / 云纹 / 铜钉
- 小型题签边缘造型

### 原因
- 纯程序画容易太“工程化”
- 这些部位最能把“戏台战报风”做出来
- 资产面积小、复用率高、对 Web 压力相对可控

## 6.3 推荐混合方案的组件
- `ui_title_plaque`
- `ui_badge_tag`
- `hud_broadcast_banner`
- `hud_status_tag`
- `settlement_title_plaque`
- `settlement_comment_stamp_row`

### 推荐做法
- 中段底板与文本布局程序化
- 两端风格件与印章类资产用 AI / 美术补
- 保留换肤空间，避免绑定死一张整图

## 8. 推荐的实装优先级

## P1：先落骨架，最快提升观感且不容易返工
1. `ui_panel_base`
2. `ui_action_button`
3. `hud_main_panel`
4. `hud_broadcast_banner`
5. `hud_status_tag`
6. `settlement_report_panel`
7. `settlement_cta_tray`

### 原因
- 这些直接决定试玩观感
- 多数可先程序化，能快速验证 Godot UI 骨架
- 后续 AI 资产补进来也不会推翻结构

## P2：补风格钉子，让“西游记古风 Q 版”站住
1. `ui_title_plaque` 头尾装饰
2. `ui_badge_tag` 签头纹样
3. `ui_stamp_badge`
4. 账本 / 卷轴角花小贴片

### 原因
- 这是风格识别度的关键，但不该先于结构
- 适合在 P1 骨架稳定后再做

## P3：补移动端与截图传播细节
1. 手机紧凑排布样式
2. 字体缩放与安全区规则
3. 结算页印章 + 评语的最终截图构图
4. 细化播报条 / 状态签的过渡动画

## 10. 推荐的下一步交接方式

### 给 UI / Godot 落地执行线
可直接拆成以下任务包：
1. **基础皮肤层任务包**：先做 `ui_panel_base` / `ui_action_button` / `ui_badge_tag`
2. **HUD 骨架任务包**：做 `hud_main_panel` / `hud_broadcast_banner` / `hud_status_tag`
3. **结算页骨架任务包**：做 `settlement_title_plaque` / `settlement_report_panel` / `settlement_cta_tray`
4. **小资产任务包**：牌匾头尾、印章、角花、签头

### 给 AI 出图 / 美术探索线
优先补这些小件，而不是整页大图：
1. 牌匾头尾
