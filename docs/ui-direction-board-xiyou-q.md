# survivor-demo UI 方向板（第一轮）

> 目标：启动一条**不阻塞主线可玩性开发**的 AI UI 探索线，围绕“西游记古风 Q 版”产出可执行方向，而不是直接改玩法代码。

## 0. 本轮定位
- 类型：探索 / 设计线
- 范围：**HUD、升级弹窗、结算页、主菜单**
- 不做：
  - 不改当前战斗逻辑
  - 不改数值 / 刷怪 / 输入系统
  - 不要求这一轮直接落 Godot UI 代码
- 交付目标：
  1. 给后续 AI 出图 / UI 设计一个统一方向板
  2. 给 UI 落地 Agent 一个可执行任务清单
  3. 先锁定视觉语言与组件边界，再决定具体资产制作

---

## 1. 组件范围

### A. HUD（局内常驻）
必须覆盖：
- 左上主信息卡：命火 / 修为 / 斩妖 / 波次 / 当前目标
- 顶部播报：阶段名 / 升级提示 / 妖潮播报
- 右上状态签：此刻最重要的一句话
- 底部操作带：暂停 / 继续 / 再闯一局（桌面与移动端共用逻辑）
- 移动端提示签：军令 / 告急 / 压阵 / 身法提示

本轮探索重点：
- 信息层级是否一眼清楚
- 西游语义是否足够统一
- 桌面 / 竖屏是否能共用同一套视觉骨架

### B. 升级弹窗
必须覆盖：
- 标题区（升级达成）
- 3 选 1 或多选项卡位（即使当前未来才扩充，也先预留）
- 单个升级条目的：名称 / 一句话效果 / 图标位 / 稀有度或推荐标签
- 弹窗主按钮 / 快捷操作提示

本轮探索重点：
- 从“功能弹窗”提升到“修为顿悟 / 神通择法”的西游感
- 保证读起来快，不做过重卷轴 UI

### C. 结算页
必须覆盖：
- 标题（通关 / 败阵 / 暂歇战报）
- 核心结果指标：时长 / 斩妖 / 最长连斩 / 劫波 / 命火状态
- 战绩评语 / 印章位
- CTA：再闯一局 / 继续试炼 / 返回主菜单

本轮探索重点：
- 更像“戏台战报”而不是普通 game over 面板
- 适合截图传播

### D. 主菜单
必须覆盖：
- 标题 Logo 区
- 开始游戏主按钮
- 次级入口：设置 / 制作说明 / 退出（或后续占位）
- 背景气氛层：云纹 / 山门 / 经幡 / 戏台感
- 版本信息角标

本轮探索重点：
- 给项目一个“第一眼世界观入口”
- 让用户在开局前就知道这是“西游古风 Q 版生存 demo”

## 2. 风格方向提案（3 选 2 优先推进）

## 方向 A：戏台战报风（优先级最高）
**一句话**：把界面做成“妖怪戏台上的战报与军令牌”。

### 关键词
- 戏台牌匾
- 描金木框
- 朱砂题签
- 墨褐底板
- 小印章 / 军令牌 / 战报条

### 视觉特征
- 面板以“横匾 + 牌签 + 账本”结构为主
- 大标题偏牌匾感，正文偏账目感
- 角部可加轻量云纹、铜钉、描金边，不要太繁
- 结果页和 HUD 的统一性最好

### 适配组件
- **HUD：非常适合**，尤其是左上主账本、右上状态签、顶部横幅
- **升级弹窗：适合**，可做成“择法令”
- **结算页：非常适合**，直接做“战报”
- **主菜单：适合**，但标题区需要再加一点舞台感避免太功能化

### 风险
- 过度写实会显老气，必须保持 Q 感与轻松感
- 装饰一多就容易压住信息可读性

### AI 出图提示词建议
- 中国古风 Q 版 game UI
- opera stage battle report
- red gold dark brown
- wood plaque, command tag, cute journey to the west
- clean HUD, readable mobile game interface

---

## 方向 B：云纹卷轴风（优先推进）
**一句话**：把界面做成“仙家卷轴 + 云纹法帖”的轻古风系统。

### 关键词
- 云纹
- 卷轴边
- 法帖
- 金线分栏
- 纸面暖米色 + 朱砂强调

### 视觉特征
- 背板偏纸卷 / 绢布
- 组件转角更圆润，更 Q
- 信息区通过金线、压纹、云纹断开，而不是重木框
- 升级弹窗与主菜单气质最好

### 适配组件
- **HUD：适合**，但需要控制透明度，避免战斗时发灰
- **升级弹窗：非常适合**，容易做成“悟道选法”
- **结算页：适合**，更像通关卷轴总结
- **主菜单：非常适合**，第一眼会更轻、更亲和

### 风险
- 如果纸感太淡，战斗 HUD 会缺力量感
- 需要额外定义危险态 / 低血量的高对比方案

### AI 出图提示词建议
- cute Chinese fantasy UI
- scroll panel, cloud pattern, warm paper texture
- journey to the west casual game menu
- gold line separators, cinnabar accents
- readable action game HUD

---

## 方向 C：小妖绘卷风（备选探索）
**一句话**：把界面做成“山野小妖图鉴 + 轻绘本”的活泼版本。

### 关键词
- 绘卷
- 山门木牌
- 小妖图鉴
- 手绘贴纸感
- 更高饱和度的暖金 / 青绿 / 朱红

### 视觉特征
- 图标与标签更像贴纸、符签、收妖牌
- 主菜单和升级弹窗会更有 IP 味
- 更适合后续拓展角色、敌人图鉴、收集系统

### 适配组件
- **HUD：中等适合**，容易偏花
- **升级弹窗：适合**，做成抽签 / 选法很有味道
- **结算页：适合**，可做“今日降妖录”
- **主菜单：非常适合**

### 风险
- 容易从“西游古风 Q 版”滑向“童书风”
- HUD 若图形太多，会影响战斗信息读取

### AI 出图提示词建议
- cute demon hunting chinese fantasy ui
- illustrated menu, sticker-like icons
- journey to the west chibi game ui
- playful ancient chinese shapes, readable HUD

## 3. 推荐方向结论

### 建议采用的主副结构
- **主方向：方向 A 戏台战报风**
- **辅助借鉴：方向 B 云纹卷轴风**
- **方向 C 仅做主菜单 / 升级弹窗参考，不作为 HUD 主体**

### 原因
1. survivor-demo 当前最需要提升的是 **HUD 与结算页的完成感**，方向 A 最稳。
2. 升级弹窗和主菜单如果只用 A，可能略重；借一点 B 的卷轴 / 云纹，会更轻巧。
3. 方向 C 更适合后续角色收集或图鉴化版本，不建议这一轮拿它做主 HUD。

## 4. 组件级设计指引

## 4.1 HUD 指引
### 推荐结构
- 左上：主账本（命火 / 修为 / 斩妖 / 劫波）
- 顶部中间：戏台播报条（标题 + 小副签）
- 右上：状态签（军令签 / 告急签 / 喝彩签）
- 底部：操作带（低调，不抢战斗视线）

### 推荐视觉原则
- 长驻信息用深底金边
- 短时播报用朱砂 / 金色强调
- 危险态用高对比朱红，不靠纯文字提醒
- 移动端提示区只保留“一句话 + 标签”

### 不要做
- 不要堆满云纹导致面板发糊
- 不要把每个数值都做成主视觉重点
- 不要让状态签、播报条、目标提示争抢同一层级

## 4.2 升级弹窗指引
### 推荐命名感
- 标题：`修为顿悟` / `择一门神通` / `法门已现`
- 选项卡：卡片上方放短签，如 `攻`, `守`, `势`, `巧`

### 推荐视觉原则
- 1 个强标题 + 3 张选择牌
- 每张牌结构固定：图标位 / 名称 / 一句话收益 / 推荐签
- 强化“选择”的神通感，不做商城卡包感

## 4.3 结算页指引
### 推荐命名感
- 通关：`大圣护场` / `今日凯旋`
- 失败：`此劫未竟` / `且再整行装`
- 暂停：`暂歇戏台`

### 推荐视觉原则
- 上部是结果标题与印章
- 中部是战报数据
- 下部是 CTA
- 数据不求多，先稳住 4~5 个核心指标

## 4.4 主菜单指引
### 推荐结构
- 顶部 Logo：可先用字标 + 云头 / 金箍 / 山门轮廓
- 中部主按钮：`踏入山门`
- 次级按钮：`整备行装` / `设置` / `离场`
- 背景：淡山影 / 云海 / 戏台帷幕，不抢字

### 推荐视觉原则
- 先做“一眼知道主题”，再做复杂装饰
- 主按钮必须极清楚，不能为了古风牺牲点击意图

## 5. AI/UI 线可执行任务清单

## 第一阶段：方向定板（最先做）
1. 为 4 个组件分别整理当前截图基线
2. 产出 3 套 moodboard：A / B / C
3. 每套至少给出：主色、边框、标题、标签、按钮、图标语气
4. 标记哪些元素可共享，哪些只适合单独页面

交付形式建议：
- 一页方向总板
- 四块组件拆页
- 每套 6~9 张参考图即可，不求大而全

## 第二阶段：低保真线框（紧跟着做）
1. HUD 线框：桌面横屏 1 套、手机竖屏 1 套
2. 升级弹窗线框：1 套
3. 结算页线框：胜 / 败 / 暂停共骨架 1 套
4. 主菜单线框：1 套

验收口径：
- 不看风格时，信息层级也成立
- CTA、数值、标题、状态优先级明确

## 第三阶段：高保真首屏（局部）
1. HUD 做 1 张高保真主视觉
2. 升级弹窗做 1 张高保真
3. 结算页做 1 张高保真
4. 主菜单做 1 张高保真

验收口径：
- 同一套视觉语言
- 能直接拿去指导后续 Godot 落地

## 第四阶段：落地切图 / 资产清单（后续，不必本轮完成）
1. 拆出可程序化绘制 vs 必须出图的部分
2. 建按钮、签条、边框、图标的资产命名规则
3. 明确 9-slice / SVG / PNG 的推荐方案

---

## 6. 推荐先做顺序

### 顺序 1：HUD
原因：
- 局内曝光最高
- 最能立刻改变试玩观感
- 还能反向校准其他页面的语气和层级

### 顺序 2：结算页
原因：
- 最适合承接“戏台战报风”
- 最容易做出截图传播感
- 结构相对稳定，不依赖玩法扩展

### 顺序 3：升级弹窗
原因：
- 当前先把骨架定好，后续真扩升级系统时能直接套
- 最适合引入“卷轴 / 选法”语义

### 顺序 4：主菜单
原因：
- 对正式产品感很重要，但不阻塞当前核心试玩
- 可以等 HUD / 结算页方向稳定后再统一收口

---

## 7. 对后续 Godot 落地 Agent 的建议
- 优先做**结构替换**，不要一上来做大图重资源背景
- 先把：
  - 标题条
  - 状态签
  - 按钮体系
  - 面板边框
  - 印章 / 标签
  做成可复用组件
- 能用程序画的边框 / 分隔线 / 底色先程序画，控制 Web 体量
- 真正要出图的优先级：
  1. 主菜单 logo / 背景氛围图
  2. 结算印章 / 标题装饰
  3. 升级图标
  4. HUD 小图标

---

## 8. 本轮结论
- **推荐主方向：戏台战报风（A）**
- **推荐辅助语汇：云纹卷轴风（B）**
- **推荐先做顺序：HUD → 结算页 → 升级弹窗 → 主菜单**
- 这条线当前适合以“方向板 + 线框 + 局部高保真”为目标，不应直接挤占玩法主线开发时间。
