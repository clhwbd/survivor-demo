# Web 试玩链接对外发送消息模板

> 用途：给企业微信 / 聊天窗口直接复制发送。
>
> 目标：减少每次手写说明不一致，让试玩用户一眼知道“先点哪里、卡住怎么办、更新后看什么”。

## 使用原则
- 语气尽量像真人发消息，不像公告
- 少讲技术词，优先讲用户下一步该做什么
- 一次只说最必要的信息，别把排查手册整段塞给对方
- 如果是手机用户，默认先按手机场景沟通

---

## 场景 1：首次发试玩链接

### 适用时机
- 第一次把试玩链接发给体验者
- 需要提前说明“第一次打开可能会慢一点”
- 希望对方知道卡住时先刷新一次，不要反复追问

### 标准模板（通用版）
```text
这是试玩链接：<在这里替换链接>

你直接点开就行，第一次打开通常会慢一点。
如果页面上的加载提示还在变化，就先继续等一下；
如果同一条提示卡很久不动，刷新一次就行。
如果刷新后还是进不去，发我一张截图，再告诉我你是手机还是电脑打开的，我这边继续跟进。
```

### 标准模板（更口语版）
```text
发你试玩链接：<在这里替换链接>

直接点开玩就行，第一次一般会比后面慢一点。
只要加载提示还在动，就先等等；
如果卡很久没变化，你就刷新一次。
还不行的话，把截图发我，我来接着看。
```

### 这类模板的重点
- 先把“第一次慢一点”说在前面，减少对方一上来就判定坏了
- 明确告诉对方：先等、再刷新、还不行再反馈
- 不解释 wasm、缓存、部署这些工程词

## 场景 2：用户反馈黑屏 / 慢加载

### 适用时机
- 对方已经回复“黑屏了”“打不开”“一直在转”“很慢”
- 需要快速引导对方做最少动作
- 想拿到后续判断最有用的信息

### 标准模板（黑屏 / 空白版）
```text
先别一直反复点，你先帮我做一步：刷新一次看看。

如果刷新后还是黑屏 / 空白，麻烦你发我：
1. 当前页面截图
2. 你是手机还是电脑
3. 用的什么浏览器
4. 现在是 Wi‑Fi 还是手机流量

你把这几个发我，我这边能更快判断。
```

### 标准模板（慢加载 / 卡在某一步版）
```text
收到。
如果页面提示还在变化，你可以先再等一会儿；
如果是同一条提示卡很久没动，先刷新一次。

如果刷新后还是一样，发我一张截图，再告诉我大概卡在哪一步，我这边继续处理。
```

### 标准模板（更安抚一点）
```text
看到了，我来跟。
你先刷新一次试试；
如果还是不行，把截图发我，再带一句你用的是手机还是电脑、Wi‑Fi 还是流量，就够了。
不用自己来回折腾很多次，我这边看信息继续排。
```

### 这类模板的重点
- 先给一个最小动作：刷新一次
- 再要最关键的信息：截图、设备、浏览器、网络
- 语气要稳，别把问题说得很吓人，也别让对方自己排很多轮

## 场景 3：新版本热更新后再发链接

### 适用时机
- 刚上线一版修复 / 优化后，重新把链接发给同一批体验者
- 需要提醒对方这次重点帮忙看什么
- 想减少“我是不是还在旧版本”的沟通成本

### 标准模板（通用回发版）
```text
我这边已经更新了一个新版本，你现在可以用这个链接再试一次：<在这里替换链接>

这次你重点帮我看看：
- 能不能正常进游戏
- 加载是不是比刚才顺一点
- 进游戏后操作有没有明显异常

如果还有问题，还是老样子，直接截图发我就行。
```

### 标准模板（带“重新打开”提醒版）
```text
新版本已经更新好了，你现在重新点这个链接试一下：<在这里替换链接>

如果页面还是停在旧画面，你先刷新一次再进。
这次主要帮我看能不能正常打开、进游戏后是不是正常可玩。
有问题直接截图回我，我继续跟。
```

### 标准模板（更像聊天版）
```text
我刚更新了一版，你现在可以再试下这个链接：<在这里替换链接>

你这次主要看两件事就行：
1. 能不能顺利进去
2. 进去后玩起来有没有明显卡住 / 不对劲

如果还有问题，照样截图发我，我继续处理。
```

### 这类模板的重点
- 明确告诉对方：已经更新，可以重新试
- 点出本轮最想验证的 2~3 个点，别让用户不知道看什么
- 保持延续性，告诉对方“还是按之前方式截图反馈”即可

---

## 可直接替换的小变量
- `<在这里替换链接>`：实际试玩地址
- 如果要更像一对一聊天，可把“你”替换成对方称呼
- 如果这轮有明确修复点，可把“这次你重点帮我看看”下面三条替换成当轮关注项

## 推荐发送习惯
- **首次发链接**：用“首次发试玩链接”模板，不要一次塞太多说明
- **对方报错后**：直接切到“黑屏 / 慢加载”模板，先拿到关键信息
- **发新版本回归**：用“热更新后再发链接”模板，把本轮验证重点写清楚

## 不建议这样发
- 不要一大段工程解释
- 不要让对方一次做很多排查动作
- 不要只说“你再试试”而没有明确下一步
- 不要每次都重写一遍口径，容易前后不一致
